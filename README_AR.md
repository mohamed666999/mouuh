# إصلاح QUANTUM APEX — Binance SL/TP + CQMI 50/50 + فريم 30m

**هذه حزمة إصلاح للكود الذي أرسلته، وليست بوتًا جديدًا مستقلاً ولا إثباتًا للربحية.** تحفظ ملفك الأصلي دون تغييره، وتولّد منه ملف Python كاملًا مستقلاً بعد التعديل.

> **أولًا: ألغِ مفاتيح Binance المنشورة في المحادثة وأنشئ بدائل. لا تستخدمها مجددًا ولا تنشر المفاتيح الجديدة.** احفظ البدائل في متغيرات البيئة أو ملف `.env` غير مرفوع إلى Git. لم تُستخدم مفاتيحك ولم تُجرَ أي عملية تداول أثناء إعداد الحزمة.

## التغييرات المطلوبة

| المطلوب | التنفيذ |
|---|---|
| SL/TP فعلية على Binance | `POST /fapi/v1/algoOrder`، ثم قراءة مستقلة بالهوية من Algo API للتحقق |
| وزن CQMI | `CQMI_WEIGHT = 0.50` |
| بقية المؤشرات | `LEGACY_WEIGHT = 0.50` لمجموعها المطبّع، **وليس 50% لكل مؤشر** |
| فريم التداول | `trading_timeframe = "30m"` للإشارة، ATR، اشتراك Kline، وسجل الصفقة |
| الشموع | الشموع المكتملة فقط؛ تقييم واحد لكل شمعة جديدة لكل رمز |
| الوقف والهدف | مضاعفا ATR الأصليان: 2.5 للوقف و5.0 للهدف، دون Trailing |
| حد الإشارة | 60/100 كما في الكود الأصلي؛ لم يُخفض تلقائيًا |

المؤشرات المعطّلة لا تدخل في بسط درجة مجموعة المؤشرات الأخرى ولا في مقام تطبيعها. ويُستبعد عامل Liquidity من هذا المقام لأنه لم يكن مساهمة اتجاهية في البسط الأصلي.

**30m هو اختيارك، وليس ادعاءً بأنه الأفضل أو الأكثر ربحًا.** لا يوجد اختبار تاريخي خارج العينة هنا يثبت أفضلية هذا الفريم أو أوزان 50/50.

## لماذا لم يكن التحقق القديم كافيًا؟

نقلت Binance أوامر USD-M Futures الشرطية، ومنها `STOP_MARKET` و`TAKE_PROFIT_MARKET`، إلى Algo Service اعتبارًا من 9 ديسمبر 2025. الإصدارات القديمة التي ترسلها إلى المسار العادي قد تتلقى `-4120`؛ ومع الإصدارات الحديثة، فحص الأوامر العادية وحده لا يثبت وجود الأوامر الشرطية. [1](https://developers.binance.com/docs/derivatives/change-log)

يستخدم الإصلاح الحقول `triggerPrice` و`algoId` و`clientAlgoId`، مع `algoType=CONDITIONAL` و`workingType=MARK_PRICE`. يرسل حماية Close-All عبر `closePosition=true` **دون** `quantity` و**دون** `reduceOnly`؛ ويحدد `positionSide=LONG/SHORT` في Hedge Mode و`BOTH` في One-way Mode. هذه القيود موثقة في New Algo Order. [3](https://developers.binance.com/docs/derivatives/usds-margined-futures/trade/rest-api/New-Algo-Order)

أُصلح أيضًا خطأ واضح في الكود: استدعاء AQII كان يمرر `(highs, lows, closes)` إلى توقيع يبدأ بـ`(closes, highs, lows)`. أصبح الاستدعاء بأسماء المعاملات. كما أصبح ATR بتنعيم Wilder من التاريخ الكامل بدل بدء الحساب من آخر 14 شمعة فقط.

## الاستخدام السريع — لا يرسل هذا الأمر أي طلب للمنصة

1. فك ضغط الحزمة.
2. احفظ الكود الأصلي الذي أرسلته في ملف، مثل `apex_original.py`، أو استخدم ملفه الموجود عندك.
3. من داخل مجلد الحزمة نفّذ:

```bash
python apply_apex_fix.py /path/to/apex_original.py -o /path/to/apex_30m_fixed.py
```

استبدل المسارين بمسارات ملفاتك. أداة التطبيق تحتاج Python 3.10+ ومكتباته القياسية فقط. **لا تستورد الملف الأصلي ولا تشغله.** تتحقق من البنية والصياغة، وتحذف المفاتيح الافتراضية المضمّنة من الناتج، ولا تكتب فوق الأصل. إذا كان المصدر مختلفًا عن البنية المتوقعة، تتوقف بدل إجراء تعديل جزئي صامت.

الناتج:

- `apex_30m_fixed.py`: نسخة كاملة مستقلة من **ملفك الأصلي** بعد إدراج الإصلاحات؛ لا تحتاج ملفات قوالب الحزمة لتعمل لاحقًا.
- `apex_30m_fixed.changes.json`: تقرير بالتغييرات، لا يحتوي المفاتيح.

ثم ثبّت المتطلبات واختبر الحزمة محليًا:

```bash
python -m pip install -r requirements.txt
python -m pytest -q tests
python -m py_compile /path/to/apex_30m_fixed.py
```

لا تُشغّل `execution_replacement.py` أو `controller_methods.py` مباشرة: هي قوالب تستخدمها أداة التطبيق.

## الإعداد الآمن والتجربة على Demo

انسخ `.env.example` إلى `.env` **بجانب الملف المولّد**. يبدأ الإعداد بـ:

```dotenv
DRY_RUN=true
APEX_USE_DEMO=true
APEX_ALLOW_LIVE_TRADING=
BINANCE_API_KEY=
BINANCE_SECRET=
APEX_ADOPT_ORPHANS=false
```

مع `DRY_RUN=true` لا يضع البرنامج Entry أو SL أو TP على Binance. لا تتوقع ظهور أوامر حقيقية في هذا الوضع. توجد محاكاة بسيطة لسجل الصفقات، وهي ليست Backtest ولا نموذج تنفيذ واقعيًا.

بعد ضبط `.env` وتثبيت المتطلبات، شغّل **الملف المولّد**، وليس قوالب الحزمة:

```bash
python /path/to/apex_30m_fixed.py
```

ابدأ بالقيم الآمنة أعلاه؛ التشغيل يحتاج اتصالًا عامًا ببيانات السوق، بخلاف أداة التطبيق والاختبارات المحلية التي لا تحتاج اتصالًا بـBinance.

لاختبار وضع الأوامر فعليًا **على Binance Demo أولًا**:

1. ضع مفاتيح **Demo جديدة** في الحقول الفارغة؛ مفاتيح Live ليست بديلًا عنها.
2. أبقِ `APEX_USE_DEMO=true`.
3. غيّر `DRY_RUN=false`.
4. ضع `APEX_ALLOW_LIVE_TRADING=I_UNDERSTAND_THE_RISK`.
5. عند تنفيذ إشارة مؤهلة، تحقق بنفسك في قسم **الأوامر الشرطية** من وجود الوقف والهدف، الجانب، سعر التفعيل، ونوع Mark Price، وطابق الهوية مع السجل.

المهم في السجل:

```text
SL VERIFIED | ... | algoId=... | triggerPrice=... | positionSide=...
TP VERIFIED | ... | algoId=... | triggerPrice=... | positionSide=...
```

ظهور رد الإنشاء وحده لا يكفي: رسالة VERIFIED تأتي بعد قراءة مستقلة. ولا يعني غياب صفقة فورية أن التنفيذ معطّل؛ الفريم 30m، حد الإشارة 60، بيانات Microstructure يجب أن تكون حديثة، وتُطبق حدود المخاطرة والحد الأدنى للكمية/القيمة.

**لا تنتقل إلى Live قبل التحقق المستقل على Demo.** التنفيذ الحقيقي يحتاج `APEX_USE_DEMO=false` ومفاتيح Live جديدة وإذنًا صريحًا؛ هذه الحزمة لم تُختبر على منصة حقيقية أو Demo. عطّل السحب في مفتاح التداول وقيّد عنوان IP والصلاحيات بحسب احتياجك. لا تعمل بالتزامن مع تداول يدوي أو بوت آخر على الرموز نفسها: Close-All يغلق كامل جانب المركز، لا صفقة محلية صغيرة فقط.

## المراكز الحالية وحدود الأمان

- فحص البداية ينتهي **قبل** بدء الماسح؛ لا سباق بين حماية المراكز القديمة ودخول صفقة جديدة.
- حالة `PROTECTED` المخزنة ليست دليلًا: تُقرأ الأوامر من Binance مجددًا عند البداية.
- محاولة الإنشاء لها Client ID ثابت؛ عند ضياع الرد، يُبحث بالهوية نفسها دون إعادة إرسال عمياء.
- إذا لم يُؤكد SL بعد دخول جديد، تُحاول إزالة الانكشاف بكمية المركز **الفعلية** والتحقق من الإغلاق. فشل قراءة المركز يعني **حالة مجهولة**، وليس كمية صفرًا. أي فشل/غموض يوقف الدخول الجديد ويطلب تدخلك؛ ليس هناك ضمان أن API المنقطع سيسمح بالإغلاق.
- إذا فشل TP مع SL مؤكد، يحتفظ بالمركز وSL ويوقف الدخول الجديد؛ لا يدّعي وجود TP.
- المراقب لا يحرك مستويات SL/TP ولا يعيد إنشاءها دوريًا. ينظف أوامر الحماية ذات الهويات المعروفة بعد إغلاق الجانب، بدل إلغاء جميع أوامر الرمز بما فيها أوامر يدوية.
- المراكز الموجودة على Binance وغير المسجلة محليًا توقف الدخول الجديد افتراضيًا. احمها يدويًا، أو فعّل `APEX_ADOPT_ORPHANS=true` **عن قصد** قبل إعادة التشغيل. تبنّي مركز بلا تاريخ محلي يستعمل 30m ATR حول Mark Price الحالي، وليس حول سعر دخول قديم متجاوز.
- إذا كان مستوى مخزّن متجاوزًا، أو توجد حماية مختلفة/متعارضة، أو محاولة حماية سابقة غير محسومة، يطلب فحصًا يدويًا بدل تكرار الأوامر أو تغيير قرارك صامتًا.
- قبل إعادة التشغيل، خذ نسخة احتياطية سليمة من قاعدة SQLite الحالية. قواعد Dry Run وDemo وLive منفصلة افتراضيًا؛ Live يحتفظ باسم `apex_quant_v4.db` الأصلي. يمكن تحديد قاعدة موجودة عبر `APEX_DB_PATH`؛ لا توجه اختبار Demo إلى قاعدة Live.
- تُحدّث أعمدة الحماية بطريقة قابلة لإعادة التشغيل، ويحفظ التنفيذ الصفقة مرة واحدة بالكمية وسعر التعبئة الفعليين وهوية أمر الدخول.
- حدود عدد المراكز والمخاطرة المتوقعة تُفحص قبل كل دخول، لا مرة واحدة لكل قائمة الرموز. لا تُرفع الكمية لتجاوز الحد الأدنى للمنصة.
- يُهيأ أساس الخسارة اليومية من أول رصيد، ولا يُستأنف التداول تلقائيًا بسبب انقضاء ساعة مع استمرار تجاوز حد الخسارة. هذه الأسس ما زالت دورية وداخل الذاكرة؛ ليست نظام مخاطرة دائمًا كاملًا عبر إعادة تشغيل العملية.

## ما الذي تم اختباره وما الذي لم يُختبر؟

**نجح 100 اختبار محلي**؛ راجع `TEST_RESULTS.md`. الاختبارات تستخدم منصة وقاعدة بيانات وهميتين وتمنع فتح اتصالات شبكة. تشمل API payloads، One-way/Hedge، فقدان الرد، حماية غير صحيحة، أخطاء القراءة، فشل SL/TP، الإلغاء، الإغلاق، البداية، ATR، الأوزان المعطّلة، وحماية الملف الأصلي أثناء التطبيق.

**لم يُشغّل الملف الأصلي على حسابك، ولم تُنفّذ أوامر Live/Demo، ولم يُثبت الناتج كاملًا ضد API حقيقي.** اختبارات تحويل المصدر تشمل مثالًا تركيبيًا يمثل البنية المتوقعة؛ يبقى فحص الملف المولّد عندك وتجربة Demo خطوة مستقلة لازمة. فحص توفر طرق CCXT جرى محليًا على الإصدار 4.5.85، وليس اختبار اتصال أو قبول أوامر.

هذا إصلاح لمسار التنفيذ وبعض الأخطاء المرتبطة به، لا تدقيقًا شاملًا لكل النماذج المعلن عنها في الرأس. لا يثبت الأساس العلمي لتسميات CQMI «الكمومية» ولا قدرته التنبؤية. ولا تضمن الأوامر الشرطية سعر تنفيذ الوقف أو تمنع التصفية/الانزلاق أثناء التقلب أو أعطال المنصة. حساب مخاطرة الوقف لا يشمل كل الرسوم والفجوات. الربح المسجل لا يُختلق من آخر Ticker؛ يُترك مجهولًا عندما لا تتوفر تعبئات مؤكدة، والربح المؤكد المذكور يستثني التمويل.

لوحة FastAPI الأصلية ليست مؤمنة بالمصادقة؛ لا تعرضها للإنترنت دون حماية مناسبة. راجع الحزمة بنفسك قبل أي تشغيل بأموال حقيقية.
